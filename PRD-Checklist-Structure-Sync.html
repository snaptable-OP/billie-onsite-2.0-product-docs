    Checklist structure sync

    PRD 05 Status: Shipped · server sweep Surfaces: Desktop checklist library → open inspections All docs

    When a checklist is saved, ms-walk appends new structure into inspections that already loaded it. Removals/renames do not erase answered snapshots. Clients do not show Syncing/Synced badges for this status.

    1

    Design intent

    • Never punish in-progress work — answered fields/items survive library edits.
    • Additive evolution — new requirements/fields appear without a second client writer.
    • Stable specials — section specials stay keyed by section id.
    • Single pipeline — server sweep after save; no live client schema overlay.
    2

    Frontend UI

    billie-web · Team Requirement Library → save → open inspection item
    Checklist editor
    3.2 Cold room check
    Save
    Same inspection · after structure sync
    Inspection form
    Synced answers kept
    3.2

    No Syncing… / Synced badge is rendered in web or mobile today. Answer sync (“Re-sync”, “All changes synced”) is a different UI.

    Authoring UI is the web checklist library. Inspectors see new fields appear on the existing form snapshot — there is no dedicated structure-sync status chrome on either client.

    3

    Feature logic

    Checklist changeExisting inspection
    Add field (new id)Appended at end of stored formSchema
    Add requirementNew item via server sweep
    Rename / edit options / remove fieldSnapshot unchanged
    Remove requirementIssue stays

    Statuses SYNCING → SYNCED are server-side only today.

    4

    User journey

    1. Inspection already exists from Checklist A.
    2. Author adds a field in Team Requirement Library → Save.
    3. Server structure-sync sweeps related walks.
    4. Inspector sees new blank field; prior answers remain.
    5

    Test cases

    IDStepsExpected results
    TC-SYNC-001

    Add form field to checklist appears on open inspection

    Pre: Inspection created from Checklist A; item has ≥1 answered field. Author can edit Checklist A.

    1. Note current answered values on the inspection item.
    2. In Team Requirement Library, open Checklist A → same requirement → add a new field (new id), Save.
    3. Wait for server sync (tens of seconds if needed).
    4. Reopen/refresh the inspection item on web and mobile.
    • New field appears at the end of the form, blank.
    • Previously answered fields keep their values and labels.
    • No second duplicate of the new field after another refresh.
    TC-SYNC-002

    Rename field label does not change inspection snapshot

    Pre: Inspection already has field X answered; checklist still linked.

    1. In the library, rename field X’s label (same field id), Save.
    2. Reopen the inspection item.
    • Inspection still shows the old label from the snapshot.
    • Answer value for that field id is unchanged.
    • New inspections created after the rename may show the new label.
    TC-SYNC-003

    Remove field from checklist leaves snapshot field + answer

    Pre: Inspection has answered field Y.

    1. In the library, delete/remove field Y from the requirement, Save.
    2. Reopen the inspection item.
    • Field Y still appears on the inspection form.
    • Prior answer for Y is still present.
    • Structure sync does not strip the field from requirement_json.
    TC-SYNC-004

    Add requirement creates a new inspection item

    Pre: Open inspection from checklist; count current items.

    1. In the library, add a new requirement under a section, Save.
    2. Refresh the inspection (journal list/detail).
    • Item count increases by the new requirement(s).
    • New item has empty form answers.
    • Existing items and answers remain.
    TC-SYNC-005

    Remove / inactive requirement does not delete inspection issue

    Pre: Inspection item tied to requirement R exists (may have notes/answers).

    1. In the library, remove or mark requirement R inactive, Save.
    2. Reopen the inspection.
    • The issue/item for R is still present (orphaned).
    • Notes and answers on that item remain.
    • Item is not auto-deleted by structure sync.
    TC-SYNC-006

    Section specials stay keyed by section id

    Pre: Checklist section has AI summary special; inspection already has the trailing special item.

    1. Edit another field on the checklist and Save (re-trigger sync).
    2. Compare the special item id before/after.
    • Trailing special item id remains the section id.
    • No duplicate special item is created for that section.
    TC-SYNC-007

    User blank item is never deleted by sync

    Pre: On inspection, add a blank item (no requirement id) with a note.

    1. Edit the checklist (add any field), Save to trigger sync.
    2. Reopen the inspection.
    • Blank item still exists with its note.
    • Blank item sorts after checklist-backed items.
