    01

    Magic Wand — single

    POST /llm_billie_service/form_field/requirement

    Runs on one requirement in the audit-report editor. Only wis_detail[].requirement.form is ever read / written; everything else passes through byte-for-byte. Steering is per requirement (no top-level guidance), and only the first ai_enabled requirement in wis_detail is processed — later ai_enabled rows are ignored and passed through unchanged.

    1.1Request

    KeyTypeReqNotes
    export_infoobjectyesGrounding context only (templateName, templateDescription, …)
    project_infoobject[]yesGrounding context only (name, address, clientName, …)
    wis_detailobject[]yesRequirement rows; completion happens in the first ai_enabled requirement.form
    sp_outputobjectyesAI report summary paragraphs; context only

    Each wis_detail[] row: row metadata + section (context) + requirement (may be null → row skipped).

    1.2Requirement fields this endpoint reads

    KeyTypeReqNotes
    ai_enabledboolnoGate. Only the first ai_enabled requirement is processed; the rest pass through. Echoed back.
    inspector_notestringyes for processed rowInstruction scoped to this requirement. Missing / blank on the first ai_enabled row → HTTP 422. Fills a blank generatable field only when the note (or the field’s own description) gives a concrete, groundable instruction — never invents facts. Rewrites Long text freely; replaces fixed-choice / Date / Time / Number / Short text only when the note states that exact value outright.

    1.3Form field shape

    { "value": "", "type": "Long text", "ai_generated": false, "options": ["Yes","No"], "description": "" }
    • type ∈ Short text Long text Number Date Time Multiple choice Checkboxes Dropdown File / image. Only Long text / Multiple choice / Checkboxes / Dropdown can be filled from blank.
    • value — string; "" = blank. Date = ISO, Time = HH:MM, Number = numeric string.
    • ai_generated — output: true on any field this call produced a value for. Optional / ignored on input.
    • ai_modified — output only, emitted only when true: the call replaced a value already on record (ai_generated is true too).
    • options — for choice types; a choice field with no non-empty options is skipped. Unknown per-field keys preserved.
    • description — form-author standing rule; applied whenever this call writes/changes the field, alongside the note; note wins on conflict. Never becomes value.

    1.4Minimal valid body

    {
  "wis_detail": [
    {
      "requirement": {
        "id": "r-1",
        "ai_enabled": true,
        "inspector_note": "Auditee agreed to complete corrective actions by 18 Sep 2026.",
        "form": {
          "agreed_completion_date": { "value": "", "type": "Date" }
        }
      }
    }
  ]
}
    Validation One wis_detail row is enough. Inside requirement only id, ai_enabled: true, a non-empty inspector_note, and a form with at least one field carrying a type are needed — a first ai_enabled requirement with a missing / blank inspector_note is HTTP 422. export_info / project_info / sp_output default to empty and can be omitted.

    1.5Response

    Same document at the top level, plus success and payload_s3_uri.

    {
  "export_info": { /* unchanged */ }, "project_info": [ /* unchanged */ ],
  "wis_detail":  [ /* first ai_enabled requirement: form fields filled / changed; rest unchanged */ ],
  "sp_output":   { /* unchanged */ },

  "success": true,
  "payload_s3_uri": "s3://wb-ai-billie/lambda_layer/form_field_requirement_…_ok.json"
}
    • payload_s3_uri — on every call the full {request, response} is archived to S3; this is its s3:// URI. null when S3 is unconfigured / upload failed (call still succeeds). Overridable via FORM_FIELD_S3_BUCKET / FORM_FIELD_S3_PREFIX.
    • success: false only on an unexpected server error → document echoed back unchanged.
    02

    Magic Wand — batch

    POST /llm_billie_service/form_field/requirement/batch

    Same wand across the whole report at once. Every requirement flagged ai_enabled and written a note for gets its fields filled / adjusted in a single synchronous call — the workflow when finalizing a report.

    Same as single

    Same carbone-payload-v4 document in / out. Same form field rules, grounding, and S3 archive.

    Batch differences

    Processes every ai_enabled + non-empty inspector_note row. Blank note → left untouched (no 422). No per-call cap.

    2.1Request / response

    Identical shape to §1. Response adds success and payload_s3_uri (filename slug form_field_requirement_batch_).

    2.2Errors

    StatusWhen
    422Request body fails schema validation. No size-limit 422, no “first ai_enabled needs a note” 422.
    200 · success:falseUnexpected server error — document echoed back unchanged.

    03

    Smart Description

    POST /llm_billie_service/form_field/smart_description

    Used while building or editing an audit-checklist template. Generates the short grey help note under a field — the “what should I record here?” instruction. It never fills the field itself; this is authoring help, not data.

    Grounding only The request is the whole carbone-payload-v4 document, but it is grounding context only — nothing in it is filled, changed, or echoed back. The response carries only the generated string.

    3.1Request

    The document trimmed so wis_detail contains exactly one requirement.form field. Zero or more than one → HTTP 422 (the only rule enforced).

    KeyTypeReqNotes
    export_infoobjectnoGrounding; defaults to {}
    project_infoobject[]noGrounding; defaults to []
    wis_detailobject[]yesRows; exactly one requirement.form with exactly one field key
    sp_outputobjectnoContext only; defaults to {}

    Inside the row only requirement.id and the field’s type are required. The field’s own description is ignored (accepted so a full document round-trips, but the note is always written from scratch). type drives phrasing. options may be explained but the note never tells the auditor which to pick.

    3.2Minimal valid body

    { "wis_detail": [ { "requirement": { "text": "Floors, walls and ceilings",
  "form": { "Floor condition": { "value": "", "type": "Long text" } } } } ] }

    3.3Response

    Only the generated string plus success — not the document.

    {
  "result": { "smart_description": "Record the date the auditee agreed the corrective actions would be completed by, as it appears in the audit close-out." },
  "success": true
}

    On failure: success: false and result.smart_description = "".

    04

    Knowledge Agent

    POST /llm_billie_service/search/memory

    A single question-and-answer against the org’s uploaded knowledge base (“memory”). Stateless — one call, one answer, no conversation.

    4.1Request

    {
  "index": 42,
  "query": "What is the corrective-action timeframe for a major non-conformance?",
  "filter_conditions": [
    { "type": "knowledge", "ids": ["kb_food_safety"] },
    { "type": "project",   "ids": ["proj_tmtp_1"] }
  ],
  "messages": ["earlier user turn", "earlier assistant turn"],
  "type": "GlobalKnowledgeQA"
}
    KeyTypeReqNotes
    indexintyesLoad-balancing counter
    querystringyesThe question. Empty / missing → success: false
    filter_conditionsobject[]yesSearch scope. Each { "type": "knowledge"|"file"|"team"|"project", "ids": […] }. Empty / missing → success: false
    messagesstring[]noPrior conversation turns; default []
    typestringnoGlobalKnowledgeQA (default) or LocalKnowledgeQA

    4.2Response

    {
  "result": {
    "answer": "Major non-conformances must be closed within 28 days …",
    "reference_ids": [1, 4],
    "context_list": [
      { "context": "…excerpt used to ground the answer…",
        "file_id": "fid_ab12…", "page_no": 7, "score": 0.82, "reference_id": 1 }
    ]
  },
  "success": true
}
    • reference_ids — the subset of context_list[].reference_id the answer actually cites.
    • Nothing relevant → result = { "answer": "No relevant information found.", "reference_ids": [], "context_list": [] }, success: true.
    • On error → result: null, success: false (HTTP 200).
    Companion POST /llm_billie_service/delete/memory with { "filename": "…fid_<uuid>_…" } removes a document from blob storage + the vector store.
    05

    Ask AI

    POST /agent_billie_service/agentic_search/*

    The conversational version of the Knowledge Agent — a chat assistant over the same knowledge base. Unlike §4 it keeps a session: it remembers the conversation and, per message, decides whether to chat, pull fresh documents, or reshape what it already retrieved, then answers with citations.

    Session lifecycle Open with init_chat (search scope) → send messages with chat_and_fetch → close with delete_chat. Session state is server-side, keyed by session_id. Call init_chat before the first chat_and_fetch. On failure these endpoints return HTTP 500 with success: false.

    5.1init_chat

    POST /agentic_search/init_chat

    Creates / seeds a session with its retrieval scope. Does not send a message.

    // request
{
  "session_id": "sess_9f2c1e7a",
  "filter_conditions": [ { "type": "knowledge", "ids": ["kb_food_safety"] } ],
  "request_mode": null,
  "request_params": {
    "background_messages": ["context the retrieval/answer should assume"]
  }
}

// response
{ "success": true }
    • filter_conditions — same shape as §4. Missing filter_conditions or session_id → success: false.
    • request_params.background_messages — extra context folded into retrieval and answering.

    5.2chat_and_fetch

    POST /agentic_search/chat_and_fetch

    Sends one user message and returns the reply plus the retrieval context in a single call.

    // request
{ "session_id": "sess_9f2c1e7a", "message": "What's the timeframe to close a major NC?" }

// response
{
  "result": {
    "session_id": "sess_9f2c1e7a",
    "reply": "Major non-conformances must be closed within 28 days …",
    "retrieved_context": [ { "reference_id": "1", "context": "…", "file_id": "fid_ab12…", "page_no": 7, "score": 0.82 } ],
    "answer_citation_ids": ["1"]
  },
  "success": true
}
    • answer_citation_ids is populated only when the turn pulled documents and the answer was not already answerable from the session’s memory; otherwise [].
    • retrieved_context is the raw document passages from the retrieve step (may be null on a pure chat turn).
    • Split variants: POST /agentic_search/chat (reply only) and POST /agentic_search/fetch_chat (full session state only).

    5.3delete_chat

    POST /agentic_search/delete_chat
    // request
{ "session_id": "sess_9f2c1e7a" }

// response
{ "success": true }

    Unknown / already-gone session → success: false (HTTP 200).
