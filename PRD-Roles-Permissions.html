    Roles & permissions

    PRD 04 Status: Shipped Surfaces: Desktop journal · Mobile inspection All docs

    Inspection roles (Manager, Host, Attendee, Viewer) decide who can open a walk and which actions desktop and mobile expose. Manager and Host share one permission set — only the label differs.

    1

    Design intent

    • One authority for forms: only Manager/Host fill forms, run Magic Wand, publish, and manage access.
    • Collaborative notes: Attendees add notes the owner can interpret into answers.
    • Safe openness after completion: project members can open completed/archived inspections as viewers.
    • Honest labels: Manager vs Host is creator vs assigned inspector — not two privilege tiers.

    4

    User journey

    1. Host opens avatar stack → Journal Access / Inspection access.
    2. Invites teammates via Add emails or people → Invite.
    3. Attendee opens item: amber/grey owner banner; form dimmed; notes still work.
    4. Host fills forms or Magic Wand, then publishes / exports.
    5. After completion, uninvited project members can open as viewers.

    Test cases

    IDStepsExpected results
    TC-ROLE-001

    Creator is Host when no assignee

    Pre: Project member with permission to create an inspection; checklist available.

    1. Create a new inspection from a checklist; do not assign another inspector.
    2. Open the inspection on desktop (Journal Access) and on mobile (Inspection access).
    3. Open an item form and confirm Magic Wand / Publish controls are available.
    • Role label on the creator is Host (not Manager).
    • Creator can fill forms, invite members, and see publish/export actions.
    • My Inspections lists the inspection for the creator.
    TC-ROLE-002

    Assigning an inspector promotes creator to Manager

    Pre: Inspection created by User A; User B is a project member.

    1. As User A, assign User B as the inspection assignee / host.
    2. Refresh Journal Access / Inspection access for both users.
    3. As User A and User B, open the same item form.
    • User A label becomes Manager; User B becomes Host.
    • Both still have full form-fill, Wand, invite, publish permissions.
    • User B appears in My Inspections and can open the walk.
    TC-ROLE-003

    Attendee sees read-only form + can leave notes

    Pre: Host has invited an Attendee to an in-progress inspection with form fields.

    1. Sign in as Attendee; open the inspection item with a form.
    2. Attempt to edit a form field.
    3. Add a text note on the item, then edit/delete that own note.
    4. Attempt to edit the Host’s note (if present).
    • Amber/grey banner shows: “Only the inspection owner can fill this form…”
    • Form fields are disabled / opacity ~0.6; values do not save from Attendee.
    • Attendee can create and edit/delete own notes.
    • Attendee cannot edit/delete someone else’s note text.
    TC-ROLE-004

    Viewer cannot open scheduled / in-progress inspection

    Pre: Inspection is scheduled or in progress; User C is a project member but not invited.

    1. As User C, open the project Inspections tab and locate the card.
    2. Click/tap to open the inspection detail (or use a direct link).
    • Card may be visible on the project tab.
    • Opening is blocked (server “User not in walk” / closed access).
    • User C does not see the inspection under My Inspections.
    TC-ROLE-005

    Viewer can open completed / archived inspection

    Pre: Same User C; Host completes or archives the inspection.

    1. As Host, mark the inspection completed (or archive).
    2. As User C (still not invited), open the inspection from the project tab.
    • Inspection opens for User C.
    • No Invite / Publish / form-edit / Wand controls for Viewer.
    • Docs / view-only surfaces remain available if shown to members.
    TC-ROLE-006

    Attendee cannot use Magic Wand or Publish

    Pre: Attendee on an in-progress inspection with notes and forms.

    1. As Attendee, open an item and look for Magic Wand / Ask AI.
    2. Open the Publish / export entry point on desktop and mobile.
    • Wand / Ask AI controls are hidden or disabled.
    • Publish / Track issues / Export actions are not available to Attendee.
    • Host still sees those controls on the same walk.
    TC-ROLE-007

    Invite requires project membership

    Pre: Host has Journal Access open; User D is on the team but not on the project.

    1. In invite search, enter User D’s email/name.
    2. Attempt to Invite User D onto the inspection.
    • Invite fails or User D cannot be added until they join the project.
    • After adding User D to the project, Invite succeeds and they appear as Attendee.
