    Roles & permissions

    PRD 04 Status: Shipped Surfaces: Project Inspections · Desktop journal · Mobile All docs

    Inspection roles (Manager, Host, Attendee, Viewer) decide who can open a walk and which actions desktop and mobile expose. A common setup path is scheduling from the project workspace and assigning a host — that is when the creator becomes Manager and the assignee becomes Host. Manager and Host share one permission set — only the label differs.

    1

    Design intent

    • Plan on desktop, execute onsite: from Project → Inspections, schedule a window, attach a checklist, and optionally Assign host so the right auditor owns the fieldwork.
    • One authority for forms: only Manager/Host fill forms, run Magic Wand, publish, and manage access.
    • Collaborative notes: Attendees add notes the owner can interpret into answers.
    • Safe openness after completion: project members can open completed/archived inspections as viewers.
    • Honest labels: Manager vs Host is creator vs assigned inspector — not two privilege tiers. Until someone else is assigned, the creator stays labeled Host.

    4

    User journey

    A · Schedule on desktop, assign a host

    1. Open a project workspace → Inspections tab.
    2. Click Schedule inspection.
    3. Enter title, From/To window, and choose a checklist; under Assign host, pick a project member (or leave unassigned).
    4. Click Schedule → toast “Inspection scheduled”; card appears with Window / Host / Checklist.
    5. If a host was assigned: open Journal Access — scheduler is Manager, assignee is Host. Both can fill forms when the inspection is open.
    6. If left Unassigned: open later via ⋮ Edit → Assign host → Save changes to flip labels the same way.

    B · Collaborate once the inspection is running

    1. Host (or Manager) opens avatar stack → Journal Access / Inspection access.
    2. Invites teammates via Add emails or people → Invite.
    3. Attendee opens item: amber/grey owner banner; form dimmed; notes still work.
    4. Host fills forms or Magic Wand, then publishes / exports.
    5. After completion, uninvited project members can open as viewers.

    Test cases

    IDStepsExpected results
    TC-ROLE-001

    Schedule inspection and assign a host → Manager / Host labels

    Pre: User A can open Project → Inspections; User B is an active project member; at least one checklist exists.

    1. As User A, open Project → Inspections → Schedule inspection.
    2. Fill Title, From/To, Checklist; under Assign host, select User B → Schedule.
    3. Open Journal Access / Inspection access for A and B.
    • Card Host = User B; lifecycle scheduled.
    • User A is Manager; User B is Host.
    • Both share Host/Manager action rights (forms, invite, publish when appropriate).
    TC-ROLE-002

    Attendee sees read-only form + can leave notes

    Pre: Host has invited an Attendee to an in-progress inspection with form fields.

    1. As Attendee, open the item form; attempt to edit a field.
    2. Add a text note; edit/delete that own note.
    3. Attempt to edit the Host’s note (if present).
    • Amber/grey banner: “Only the inspection owner can fill this form…”
    • Form fields disabled; Attendee can create/edit/delete own notes only.
    TC-ROLE-003

    Viewer cannot open scheduled / in-progress inspection

    Pre: Inspection is scheduled or in progress; User C is a project member but not invited.

    1. As User C, locate the card on the project Inspections tab.
    2. Click/tap to open (or use a direct link).
    • Opening is blocked (server “User not in walk” / closed access).
    • User C does not see it under My Inspections.
