    Track Issues · AI payload

    PRD 09 Status: Shipped Surfaces: Mobile Track issues · Desktop Publish to Project · ms-walk AI All docs

    Track Issues AI now uses form field values as well as notes when generating Subject, Details, Tags, and related draft fields. Filled answers are part of the LLM payload — not only frozen onto the WIS afterward.

    1

    Design intent

    • Forms inform the write-up: answered fields (labels + values) are included in the AI generation payload so drafts reflect structured capture, not notes alone.
    • Notes still contribute: text / voice / markdown remain in the same generation call and combine with form context.
    • Freeze is separate: form answers still land on the WIS requirementJson for follow-up — that freeze does not replace sending values to the LLM.
    • Empty forms do not invent answers: blank fields are omitted or treated as empty context; AI should not fabricate form values.

    Mobile: Track issues generation payload includes answered form fields for each item, alongside notes.

    3

    Feature logic

    InputIn AI payload?Effect on draft
    Note text / voice / markdownYesSubject, Details, Tags (and related extractors)
    Form field answers (label + value)YesUsed with notes so generated copy can cite measured / selected values
    Blank / unanswered form fieldsNo*Omitted from payload; must not invent values
    Form answers on WIS—Still frozen onto requirementJson after generation (unchanged)

    * Only non-empty answers are meaningful context. Forms-only items (no notes) can still generate from answered fields. Attachment-only / empty context remains a low-signal path.

    CaseConditionAI generation
    ANotes + filled formsYes — both in payload
    BForms only (answered)Yes — form values drive draft
    CNotes only (no form answers)Yes — notes only
    4

    User journey

    1. On an item, fill form fields and (optionally) capture notes.
    2. Publish → Track issues / Publish to Project Workspace → Next.
    3. Billie generates Subject / Details / Tags using notes + form values in the AI payload.
    4. Review draft: Details should reflect key form answers; forms also remain frozen on the WIS.
    5. Select and publish.

    Pre: Host; item has answered form fields with distinctive values (e.g. Temperature = 8.2, Pass/Fail = Fail). No text, voice, or markdown inspector notes on the item.

    1. Confirm the form is saved and the notes thread is empty.
    2. Publish → Track issues (mobile) or Publish to Project Workspace (desktop) → Next.
    3. Wait for generation; open Subject, Details, and Tags on the draft.
    • AI completes successfully (no empty / failed generation solely because notes are missing).
    • Subject and/or Details are grounded in the answered form field labels and values.
    • Draft is usable for review and publish like a notes-backed item.
