    Trackable issues

    PRD 11 Status: Partial Surfaces: Desktop checklist library · Desktop Track Issues · Mobile (gap) All docs

    Authors mark requirements Trackable or not. Non-trackable items should start unselected (Not trackable) in Track Issues, but can still be included manually. Mobile and structure-sync do not fully honor the flag yet.

    1

    Design intent

    • Not every checklist row is a finding (e.g. sign-off).
    • Author sets defaults; inspector decides the final publish set.
    • Missing flag = trackable (legacy-safe).
    • Independent of Looped / Blank after / Notes / Include-in-AI-summary.

    3

    Feature logic

    • trackableIssue?: boolean on REQUIREMENT — only false opts out.
    • Web JournalPublish: starts unselected + Not trackable; manual Include allowed.
    • Gap: ms-walk drops flag on bootstrap; mobile has no pre-deselection.
    4

    User journey

    1. Author turns Trackable off on Final sign-off.
    2. Host opens Publish → Preview and Edit Before Publish.
    3. Sign-off shows Not trackable; findings stay selectable.
    4. Publish selected finding items.
