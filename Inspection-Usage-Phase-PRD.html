    01

    Purpose

    Transform the product from an issue-logging tool into an inspection and report-generation workflow for field inspectors.

    The usage phase must let inspectors start an inspection on site, capture evidence and findings, use AI assistance, review outputs, sign off, and publish a report from mobile or desktop.

    02

    Goals

    • Let inspectors start an inspection directly on site without office scheduling.
    • Support quick manual entry for structured data and AI assistance for narrative content.
    • Preserve inspector control through review, editing, and conflict handling before publication.
    • Generate reports from inspection data using either customer-specific or default templates.
    • Make inspections and reports accessible on both mobile and desktop.

    Users

    User Primary needs
    Field inspector Start inspections, capture structured answers, photos, findings, signatures, and publish reports
    Inspector returning from site Use AI once internet is available to expand narrative fields and incorporate document references
    Manager View team inspections and reports

    06

    Inspection lifecycle

    6.1Design intent

    Give inspectors a clear, filterable lifecycle for every inspection—from empty/scheduled through active capture to completed—while separating inspection lifecycle from report publish status. Rename Journal → Inspections in the product surface.

    6.2Feature descriptions

    Terminology

    Rename Journal to Inspections throughout the product. Partial  Tab = Inspections; legacy strings and API identifiers remain.

    Lifecycle statuses

    Status Target definition Current behavior
    Scheduled Future-dated inspection with no entered data Empty inspection or “start from scratch.” scheduledAt field exists but is not set — future-date scheduling is not implemented
    In Progress Data entry has started Set when checklist is selected, content exists, or first answer entered
    Completed Report published for the inspection Also triggered when walk is archived or all publishable issues are published to workspace — may diverge from “report file exported”

    Report status (secondary axis)

    Separate from lifecycle, report status currently intrinsically indicates:

    Report status Meaning
    Not published No export or workspace publish
    Pending Publish in progress
    Published Report file exists and/or items published to workspace
    Current stateComputed client-side (published | pending | not_published) but not displayed on inspection list cards. May decide to display in the future.

    6.3Limitations

    • Future-date Scheduled inspections are not implemented (scheduledAt unused).
    • Completed can mean archive, workspace publish, or report export—canonical rule is still open (§12 / §20).
    • Report status is computed but not shown on list cards.
    • Journal → Inspections rename is partial (tab label vs legacy copy and API IDs).
    • Report template name is modeled on cards but often shows “No report template” because export choice is not persisted to inspection metadata after export.

    6.4User journey expected

    1. Inspector opens Inspections tab.
    2. Filters by Scheduled / In progress / Completed.
    3. Card shows checklist name; report template name may show “No report template” if export choice was not persisted.
    4. Swipe archive toggles lifecycle locally (optimistic).
    5. An inspection started directly on site appears as In Progress once the inspector begins entering data.

    7.2Feature descriptions

    08

    Form completion

    8.1Design intent

    Let inspectors manually complete structured fields on site (including offline), with clear sync state, fast photo capture/markup, and optional image-to-text drafts for notes—without forcing AI for discrete answers.

    8.2Feature descriptions

    Supported inspection input

    Field type Target Mobile support today
    Short text Yes Implemented
    Long text Yes Implemented
    Multiple-choice (single selection) Yes Implemented
    Date Yes Implemented
    Number Yes Implemented
    Photo capture Yes Implemented
    File attachment Yes Limited — non-image types mapped to image flow currently (need to double-check JSON)
    Signature Yes Implemented
    Multi-select checkboxes Yes Gap — backend checkboxes rendered as single-select (target: multi-select)
    Time Yes Gap — rendered as short text, no time picker; implement next
    Dropdown Yes Implemented (single select)
    AI summary (ai_summary) Yes Implemented — generate/regenerate via Sparkles; host-authored (see §10)

    Manual-first capture loop

    Inspectors must be able to manually complete fields while on site, including offline. Discrete fields (compliant/non-compliant, yes/no) are especially important offline.

    Form capture loop Implemented — host owns form values

    1. Inspector navigates issue carousel (each item = one checklist requirement instance).
    2. Forms render inside the item via requirement journal block.
    3. Answers stored locally: formAnswers[walkId][issueId][fieldId].
    4. When online: 1s debounced autosave; on reconnect, batch sync flushes pending issues.
    5. Conflict model today: server answers replace local wholesale on fetch — no field-level merge. Host is authoritative for form values; collaborators contribute via notes (§16).

    Sync status icons Batch-2

    Form field values and inspector notes carry sync status so offline ↔ online work stays visible:

    • Green tick — successfully synced (SENT).
    • Grey clock (or spinner while uploading) — pending / in flight (PENDING / UPLOADING).
    • Red exclamation — sync failed (FAILED).
    • Empty fields show no sync icon. Notes use the same visual language where status applies.
    • Autosave / reconnect paths flush pending form answers and local form images when online.

    On Publish → Export report → choose template → Continue, if unsynced (pending/failed) data remains, a warning modal appears (completed-field count, review warning, Open Progress / Proceed anyway / dismiss). See §12.

    Camera capture Batch-2

    In-app camera (Vision Camera) supports familiar phone-camera behaviors, then hands off to markup / compression / save:

    • Front / back camera switch; torch / flash where hardware allows; zoom; tap-to-focus; shutter.
    • After capture, flow typically continues to photo editor / markup, then compression and attachment to notes or form image fields.
    • Gallery pick remains available as an alternative to live capture.
    • Optional behaviors: timestamp watermark, save to device album (product / plan dependent).

    Photo markup Batch-2

    After capture (or from editor entry points), inspectors can add shape stickers — arrows and rectangles (and related shapes such as ellipses, depending on platform), with multiple colors; stickers can be dragged, scaled, and rotated. Edited image is saved/uploaded as the attachment used downstream. Android may also expose draw-mode shape tools; iOS uses the native photo-editor shape sticker container.

    Image-to-text on note photos Batch-2

    On the inspector’s own photo messages in inspector notes, a Sparkles control runs image-to-text against the uploaded image URL. The caption is inserted as a draft in the note composer (not auto-sent). Related: form image fields may offer a separate control that generates text into the notes thread (upload URL required). This is not Ask AI RAG image recognition—see §11.

    Form usability — continuously improved

    Validate improvements for long forms and large option sets:

    • Stronger visual indication of selected binary or multiple-choice responses (color codes).
    • Alternative layouts for long multiple-choice lists.
    • Clear visibility of complete vs incomplete fields (required flags, completion checks, publish tag derivation).

    No hard limit on option count; long forms may use multiple forms or sections. UI or cosmetic improvements on form usability will be a work in progress — do not expect perfect polish in this release.

    8.3Limitations

    • Multi-select checkboxes and dedicated time picker remain gaps.
    • File attachment non-image types are limited / need JSON verification.
    • Export unsynced warning is a guardrail, not a hard block— Proceed anyway is allowed.
    • Sync retries are capped; persistent failures need user attention (retry / Re-sync / connectivity).
    • Camera requires permission; behavior varies by device; large images are compressed (plan rules may alter compression).
    • Markup stickers are raster overlays (not editable vector layers after save); iOS/Android tool parity may differ slightly.
    • Image-to-text: own note photos only; needs network + uploaded URL; draft quality depends on photo/model; does not auto-fill structured form fields.
    • Full multi-author merge of the same form field is not solved (host-owned form model)—see §16.

    8.4User journey expected

    1. Host (or solo inspector) opens an item and fills discrete/manual fields; icons show sync state.
    2. Captures a photo from notes or an image field → optionally marks up with arrow/rectangle → confirms attachment.
    3. On an uploaded note photo, taps Sparkles → edits draft caption → sends note (or discards).
    4. While offline, grey clocks remain; on reconnect, icons move to green (or red if failed).
    5. Before export, if anything is unsynced, warning modal offers Open Progress or Proceed anyway.
    09

    Findings and repeated items

    9.1Design intent

    Treat findings as structured form fields on checklist items—not a separate entity—and let inspectors duplicate or insert items on site when the same requirement applies again, while keeping final sign-off sections last.

    9.2Feature descriptions

    Findings structure

    Data model: Findings are not a separate entity. They are form fields on checklist items (e.g. Compliant?, Finding category, Evidence, Action, Photo in the food-safety demo).

    A finding record may include: Location · Compliance status · Short defect / non-compliance description or relevant clause · Comment · Action required · Photos.

    Duplicate and insertion behavior

    Action Behavior (current)
    Duplicate current item Copies requirement structure only (and carries over requirement ID in the JSON output); form values and inspector notes not copied
    Insert position Immediately after focused item (createdAt ordering); later items shifted
    Add blank item New issue without requirements, blank for notes capture; appears in content[] in the JSON
    Final section / sign-off placement Final checklist section(s) always remain last in carousel after any insert or duplicate — unless the final item itself is duplicated, in which case the duplicate appears immediately after it

    Sign-off is implemented as signature fields on designated final checklist section(s), not a dedicated sign-off route.

    Checklist creation and on-site usage

    • Long checklists pre-create one carousel item per requirement at start.
    • Inspector duplicates an item when the same checklist section applies again on site.
    • Newly added or duplicated findings must remain before the final sign-off section.
    • JSON output will contain the duplicated items with identical requirement ID for looping.

    9.3Limitations

    • Duplicate does not copy answers or notes—structure and requirement ID only.
    • Blank items are free-form notes capture without requirements.
    • Per-client toggle to disable blank-capture is a future product request (not this release).

    9.4User journey expected

    1. Inspector walks requirement-by-requirement in the carousel.
    2. When the same section applies again, duplicates the current item (blank answers/notes).
    3. Optionally adds a blank item for free-form notes capture.
    4. Final sign-off section(s) stay last unless the final item itself was duplicated.
    10

    AI assistance: Magic Wand

    10.1Design intent

    Hybrid workflow: offline capture on site, then AI drafts or improves narrative content after connectivity returns—with visible AI-modified attribution and Tap to undo so trust stays high. Magic Wand (and AI summary generate) are host-only.

    10.2Feature descriptions

    Modes

    Mode Requirement Current implementation
    Item-level Run Magic Wand for one finding or form item POST /form-fields/requirement — may modify existing values
    Batch Run across multiple items in parallel POST /form-fields/requirement/batch — may modify existing values; skips rows without journal notes; max 100 requirements per AI API call, but backend splits into batches (e.g. 300 items → 3 AI calls). Assume no limits from the user's perspective.
    Manual + AI Manual entry before or after AI Supported

    Eligible fields: short text, long text, number, date, yes/no, multiple-choice. Currently excludes image and signature. Host-only — collaborators cannot run Magic Wand.

    Special AI summary fields Batch-2

    • Checklist may include special AI fields of type ai_summary (e.g. Closing summary).
    • Authors configure contributing fields (includeInAiSummary) and optional preset instruction (smartDescription) in checklist / team settings on web—not on the mobile inspection screen.
    • On the item form: editable text area, chips for contributing field labels, and an AI (Sparkles) button to generate or regenerate.
    • Generation collects opted-in answers across the walk, calls the forms-summary API, writes returned text into the field (fully editable afterward).

    AI-modified indication Batch-2 · Current

    • After Magic Wand runs, fields AI writes are marked AI-modified (persisted with answer metadata).
    • On the item form: AI star / compact chip next to the field label.
    • On Progress: any item with at least one AI-modified field shows an AI modified pill.
    • Manual editing of a field clears its AI-modified mark.

    Tap to undo Batch-2 · Current

    • On each AI-modified form field, Tap to undo (with AI star) restores the previous value stored when AI wrote the field and removes the AI-modified mark.
    • Undo is per field; one previous snapshot only (no multi-step AI history).
    • Orthogonal: manual undo to last synced baseline may exist for non–AI-modified, already-synced fields.

    Conflict / overwrite handling

    Trust layer (current): AI-modified badges + Tap to undo make overwrites visible and reversible. Dedicated conflict-chooser UI for discrete fields remains a target gap.

    Field type Target behavior Current state
    Discrete fields Manual values persist unless conflict detected; surface indicator; preserve manual value pending review Batch: intent not to overwrite manual entries. Item-level: may overwrite. Attribution + Tap to undo are live; dedicated conflict-chooser UI still to be added.
    Long narrative AI may rewrite or add; not every difference is a hard conflict Partial+ — AI-modified indication and Tap to undo available
    All fields Review and edit before publication Supported via form editing

    Offline behavior & performance

    • Magic Wand and AI summary generate disabled offline (network required).
    • Manual structured entry remains available offline.
    • Today: cannot start a new inspection and load a checklist while offline. (Future: may allow previously loaded checklists to be opened offline.)
    • Performance: validate with larger volumes of findings; current performance acceptable in the demonstrated flow.

    10.3Limitations

    • Host-only; collaborators cannot create AI-modified states via Wand.
    • Indication is tied to Magic Wand (and related AI write paths)—Ask AI insert into notes does not mark form fields.
    • Image and signature fields are outside Magic Wand fill eligibility.
    • Only the latest AI write’s prior value is retained for undo; repeated wand runs overwrite it.
    • AI summary: contribution mapping authored on web; generation needs network and usable contributor answers; Progress pill does not list which fields changed.
    • Dedicated discrete-field conflict-chooser UI is not built.

    10.4User journey expected

    1. Host (and/or collaborators via notes) captures onsite notes per item.
    2. After connectivity returns, host runs Magic Wand on current item or all forms.
    3. Batch skips requirements without notes.
    4. Fields written by AI show AI-modified affordances; Progress shows AI modified pills.
    5. Host taps Tap to undo on any disagreed value, or edits manually.
    6. If an AI summary field exists, host taps Sparkles to generate, then edits the summary text.
    11

    Knowledge Agent (Ask AI)

    11.1Design intent

    Retrieve relevant information from linked documents (e.g. technical reports) and insert into the inspection. Example: identify and state the most relevant clause or condition in concise language.

    11.2Feature descriptions

    User flow

    1. Inspector completes initial observations and manual responses (in journal notes).
    2. Inspector opens Ask AI (host-only; disabled offline).
    3. Inspector selects knowledge agent tied to document set.
    4. Knowledge Agent returns a compiled answer with source document links (not full doc excerpts).
    5. Inspector Insert or Copy — operates on compiled answer, inserted into inspector notes (not form fields directly).
    6. Ask follow up opens nested sheet; session persists until Back to agent picker; Fold returns to notes without losing state.
    7. Inspector may rerun Magic Wand to incorporate inserted reference into narrative fields.

    Non-mock walks use richer Ask AI with doc filters, voice input, chat history, and preview-before-insert dialog.

    Requirements

    • Display compiled response and referenced source documents (links only).
    • Allow insert into inspection (notes today; direct field insert = future enhancement).
    • Preserve original observation when refilling with added context.
    • During re-run of Magic Wand — apply conflict logic when added information contradicts structured answers (target; dedicated conflict-chooser UI not built; attribution + undo apply via §10).

    Session persistence

    Action Behavior
    Fold / dismiss Ask AI Preserves answer and follow-up trail
    Back to agent selection Clears session
    Reopen Ask AI Restores prior answer or follow-up sheet state (if “Back to agent selection” was not triggered)
    Not Ask AI Image-to-text on note photos (§8) is a separate Sparkles vision path that drafts note captions. It is not Ask AI document RAG. Ask AI still has no image recognition for knowledge retrieval.

    11.3Limitations

    • Ask AI has no image recognition for RAG / knowledge retrieval (photos are not query inputs to the Knowledge Agent).
    • Insert target is inspector notes only this release (not form fields directly).
    • Host-only; disabled offline.
    • Performance slower than Magic Wand; optimization needed.

    11.4User journey expected

    1. Host captures notes, then opens Ask AI and picks a knowledge agent.
    2. Reviews compiled answer + source links; Insert or Copy into notes.
    3. Optionally asks follow-ups; Fold preserves session; Back to agent clears it.
    4. Reruns Magic Wand on the item so narrative fields pick up the inserted reference.
    12

    Review, preview, and report generation

    12.1Design intent

    Before publishing, give hosts a single place to scan completion, sync risk, and AI review signals—then generate a report (or publish to workspace) with guardrails when data may still be unsynced.

    12.2Feature descriptions

    Pre-publication review

    Before publishing, inspectors must review and manually change entered or AI-generated responses via form and notes editing.

    Publish to workspace path

    Walk Summary reviews items with requirement and form values, assignee, status, location, tags before WIS publish.

    Export path

    Generates report immediately after template selection; no rendered pre-export gate today. (Aim to add a preview step with in-app doc editor, but not in this release.)

    Progress sync, Re-sync & search Batch-2

    Progress (item list drawer) shows each item with:

    • Optional field completion bar (filled / total).
    • Aggregate sync icon for the item (priority: failed → pending/uploading → all sent).
    • AI modified pill when any field on that item is AI-modified (§10).
    • Header includes Re-sync, which triggers a walk-level resync (flush local form images where needed, batch sync pending issues / answers with retries).
    • Opening Progress refreshes status badges after wand / edits.
    • Search (“Search items…”) filters the list client-side by item title / numbering and requirement text. Tapping a result navigates to that carousel item. Does not search form answers, note bodies, or sync / AI status.

    Unsynced export warning Batch-2

    On Publish → Export report → choose template → Continue, if pending/failed data remains, a warning modal shows completed-field count vs total, a review warning, and actions: Open Progress, Proceed anyway, or cancel/dismiss.

    Dual publish paths

    Path Purpose Result
    Export as document default Generate Word/PDF/Excel report file Post-export preview opens
    Publish to project workspace Create/track WIS items in project Walk summary assign/publish flow
    Open decisionDoes Completed require file export, workspace publish, or either? To be clarified.

    Report template selection

    • Chosen at export/publish time, not at inspection create.
    • Team Carbone templates filtered by checklist ID.
    • Default templates (PDF/Excel/Word) from backend when no custom template.
    • Checklist can be linked to multiple template IDs; user can override report template for the same record (e.g. one for external distribution, one for internal circulation).
    • Export regenerates walk summary first to freeze latest form answers.
    • Gap selected template not persisted on inspection metadata after export. (Not sure if this linkage is needed yet.)

    Default report templates

    Required formats when no custom template: Word, PDF, Excel. Default templates should be redesigned to reflect checklist content and polished output (backend/design scope).

    Mobile report preview

    Capability Status
    Preview after export (PDF/Word/Excel) Implemented — download, share, re-open
    Preview before committing export/send Not implemented — gap currently filled by preview / edit of the forms

    Before export or sending, the inspector must be able to verify: responses, project information, preset fields, formatting, signatures. Target = pre-export rendered preview.

    12.3Limitations

    • No rendered pre-export report preview this release.
    • Progress aggregate sync icon does not show per-field detail on the list row.
    • Progress search does not filter by sync status or AI status.
    • Unsynced export warning allows Proceed anyway (not a hard block).
    • Re-sync depends on network; failed icons persist until resolved.
    • Selected export template not persisted on inspection metadata.

    12.4User journey expected

    1. Host opens Progress; scans red/clock icons and AI modified pills.
    2. Optionally searches for an item by requirement text; taps to jump to the carousel.
    3. After reconnecting, taps Re-sync; icons update toward green.
    4. Publishes → Export report → selects template → Continue.
    5. If unsynced data remains, warning modal appears → Open Progress to fix, or Proceed anyway.
    6. Reviews post-export file (download / share) and/or publishes selected items to workspace.

    Publishing, reports, and distribution

    13.1Design intent

    After export or workspace publish, inspectors and managers must download, share, and find reports again—quickly among many exports—without leaving the project Reports experience.

    13.2Feature descriptions

    Publish

    Publishing a report changes inspection status to Completed (see open decision on canonical definition).

    Post-publication access

    • Download report locally.
    • Send report out.
    • Find latest export from relevant project.
    • Re-download reports later.

    Journeys today

    • Project → Reports tab: export files grouped by inspection, not template.
    • Preview action bars: open, download, share.

    Report organization & search

    Current

    Grouped by journal / inspection as in the existing UI. Implemented keyword search on Project Reports filters the in-memory list (case-insensitive substring) across file name, template name, inspection title, published by, and file type. Empty query shows the full list.

    Target

    Grouped by template first, then inspections (template-first organization still a target).

    13.3Limitations

    • Reports search is client-side on already loaded reports—not a full server search index.
    • Does not search inside report PDF/DOCX content.
    • Template-first grouping is still target; current grouping is by inspection.
    • Relies on metadata present on the report records.

    13.4User journey expected

    1. User opens a project → Reports tab.
    2. Types part of a report or inspection name (or template / publisher / file type).
    3. List filters to matching reports.
    4. User opens, shares, or downloads the desired report.

    15.2Feature descriptions

    Desktop

    16

    Multi-inspector collaboration

    16.1Design intent

    Support team fieldwork: one host owns structured answers and AI fill, while invited teammates contribute evidence in notes (text and photos) without corrupting the form of record.

    16.2Feature descriptions

    Current — host + notes collaboration Batch-2

    • Host can invite team members into the inspection (journal / walk access).
    • Collaborators can: open the inspection; add text and photos in inspector notes on items; view forms (typically read-only).
    • Collaborators cannot: edit form field values; run Magic Wand.
    • Host can: fill and edit all form fields; run Magic Wand; use AI summary generate, etc.
    • Progress / header may show owner and invited member chips; item cards can show collaborator commenter avatars.
    • Publish / export remains a team workflow (members on the walk may publish depending on product rules); form authority stays with the host.

    Current (shipped)

    Host-owned forms + collaborative notes. Host interprets collaborator notes into forms (manually or via Magic Wand).

    Future / target — multi-author forms Not this release

    Full multi-author form merge: each inspector can contribute to every form field (including offline); on sync, values show author, time/date, and value; host confirms final value for the report (choose one or show all). Requires field-level author/timestamp in JSON and a different conflict UI.

    16.3Limitations

    • No full multi-author merge UI for conflicting form values (deferred).
    • Collaborators rely on notes for input; host must interpret notes into forms.
    • Invitation is team-scoped; non-team guests follow invite / pending-join rules of journal access.
    • Read-only form UX for collaborators is opacity / pointer lock—not a separate “viewer app.”

    16.4User journey expected

    1. Host creates inspection and invites teammates.
    2. On site, collaborator opens the same inspection and posts photos / comments on an item.
    3. Host opens that item, sees collaborator notes, fills form (or runs Magic Wand).
    4. Host reviews Progress and publishes / exports the report.

    End-to-end onsite day (reference narrative)

    17.1Design intent

    Provide one reference day-in-the-life that stitches create → capture → AI → Progress → publish so product and engineering share a single end-to-end expectation (including batch-2 mobile behaviors).

    17.2Feature descriptions

    This section is a composite narrative only — behaviors are specified in §§6–16. It assumes host authority for forms / Magic Wand / AI summary, collaborator notes input, sync icons, Progress search / Re-sync, and soft unsynced export guardrails.

    17.3Limitations

    • Reference path, not a test script; edge cases live in §18.
    • Offline create of a new inspection still requires signal to load a checklist.
    • Form multi-author merge remains future (§16); notes collaboration is the current team model.

    17.4User journey expected

    1. Host starts inspection on phone → pick project + checklist; optionally invites collaborators.
    2. Walk site requirement-by-requirement; enter yes/no and photos (camera + markup); sync icons show pending while offline.
    3. Dictate/type notes per item; collaborators may add note photos/comments.
    4. On own note photos, host (or note author) may run image-to-text → edit draft → send.
    5. Duplicate item when same checklist section / requirement applies again downstream.
    6. Regain signal → host batch Magic Wand fills narrative fields from notes; AI-modified badges appear; undo any disagreed values.
    7. Open Ask AI on tricky clause → insert compiled answer into notes → rerun wand on item.
    8. If present, generate AI summary field; edit as needed.
    9. Open Progress → search items, scan sync / AI pills, Re-sync if needed.
    10. Complete signature section(s).
    11. Publish → choose export template → Continue (unsynced warning if needed) → review generated file → share/download.
    12. Optionally track selected findings to project workspace.
    13. Manager finds report under Project → Reports (search by name/template/etc.); inspector sees inspection marked Completed.
