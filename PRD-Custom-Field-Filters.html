    Custom fields as filters

    PRD 10 Status: Shipped · UI gaps noted Surfaces: Desktop All Issues · Mobile Issues filter All docs

    Project dropdown custom fields appear under Custom Fields in the WIS filter UI. Option IDs filter via customFieldValueIds — not used on inspection lists.

    1

    Design intent

    • Team-defined dropdowns should filter the issues board like tags.
    • Dropdown-only — text CFs are not filterable.
    • OR within a field, AND across fields.
    • Desktop saved views persist CF selections as chips.

    Feature logic

    • Filterable: dropdown with ≥1 option, not INACTIVE.
    • Request: customFieldValueIds.
    • Known gaps: desktop CF-only filterActive / saved-view validation; mobile saved-view path may omit CF ids.
    4

    User journey

    1. Attach dropdown CF to project; set values on WIS.
    2. Open Filter → Custom Fields → check options → Apply.
    3. Desktop may save view; chip shows Severity: High.
    5

    Test cases

    IDStepsExpected results
    TC-CFF-001

    Custom Fields section hidden when nothing filterable

    Pre: Project has no dropdown custom fields (or only text CFs / empty options).

    1. Desktop: open Filter / View Filter Settings.
    2. Mobile: open Issues filter sheet.
    • No Custom Fields section is shown.
    • Other sections (Tags, Assignees, etc.) still appear as configured.
    TC-CFF-002

    OR within one custom field

    Pre: Dropdown CF Severity with High and Medium; WIS exist for each.

    1. Open Filter → Custom Fields → Severity.
    2. Check High and Medium; Apply.
    3. Review the issues list.
    • List shows items matching High OR Medium.
    • Items with neither option are hidden.
    TC-CFF-003

    AND across two custom fields

    Pre: Severity and Trade dropdowns both on project; WIS with combinations.

    1. Check Severity=High and Trade=Electrical; Apply.
    • Only items that match both fields remain.
    • High + other trade is excluded.
    TC-CFF-004

    Desktop saved view chip shows field name

    Pre: User can create/edit views; CF filter applied.

    1. Apply Severity=High; save/update the view filter settings.
    2. Observe view header chips.
    • Chip group label is Severity: with option High.
    • Toast may show “View Filters Updated”.
    • Known gap: CF-only criteria may fail validation / filterActive chip — log if observed.
    TC-CFF-005

    Mobile ad-hoc Apply sends customFieldValueIds

    Pre: Mobile; dropdown CF with options; WIS valued.

    1. Open Filter → Custom Fields → select an option → Apply.
    2. Confirm list updates; clear/reset and Apply again.
    • List narrows to matching WIS.
    • Reset clears CF selections.
    • Known gap: loading a saved view may omit CF ids — compare ad-hoc vs saved view.
    TC-CFF-006

    Text custom fields never appear as filters

    Pre: Project has a text CF and a dropdown CF.

    1. Open Filter → Custom Fields.
    • Only the dropdown CF (with options) is listed.
    • Text CF name does not appear as a filter group.
