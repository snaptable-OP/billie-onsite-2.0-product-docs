    Image with metadata

    PRD 06 Status: Shipped Surfaces: Desktop form builder · Desktop journal · Mobile inspection All docs

    Form type Image with metadata: multiple photos, each with nested authored fields and per-photo notes. Photo Magic Wand fills nested metadata from notes — not EXIF/geotag.

    1

    Design intent

    • Evidence + structure — each photo carries the same typed metadata.
    • Notes as AI fuel — text/voice notes ground photo Magic Wand.
    • Author once, capture many — nested schema defined in builder.
    • Offline-tolerant — add photos offline; voice transcribes online.

    3

    Feature logic

    • Type image_with_metadata; nested metadataFields[].
    • Nestable: short/long text, number, date, time, multiple_choice, checkboxes, dropdown, signature.
    • Answer: [{ id, url, metadata, notes[] }]; filled when ≥1 photo.
    • Wand: POST /form-fields/requirement grounded on photo notes.
    4

    User journey

    1. Author adds Image with metadata and nests fields under Metadata fields.
    2. Inspector Add photo → opens Photo details.
    3. Adds notes (type/voice), optionally marks up.
    4. Taps wand → nested metadata fills; edits as needed.

    Test cases

    IDStepsExpected results
    TC-IWM-001

    Author nests metadata fields under Image with metadata

    Pre: Edit access to Team Requirement Library / Forms builder.

    1. Add field type Image with metadata to a requirement form.
    2. In Field settings → Metadata fields, add Date and Dropdown nested fields; set labels; mark one Required.
    3. Confirm canvas preview; Save checklist.
    • Palette shows “Image with metadata”.
    • Teal preview shows “Add image” and “METADATA FOR THIS IMAGE” with nested fields.
    • Nested Date/Dropdown persist after reload; file_upload / nested image_with_metadata are not offered.
    TC-IWM-002

    Photo Magic Wand blocked when photo has no notes

    Pre: Inspection item with Image with metadata field; nested fields have Smart Description.

    1. On desktop or mobile, Add photo to the field.
    2. Open the photo; leave notes empty.
    3. Tap the wand (Fill metadata from notes / Fill form from this photo's notes).
    • Wand does not fill metadata.
    • User sees guidance such as “Add a note to this photo first” or “Nothing in the notes to fill the metadata with.”
    TC-IWM-003

    Photo Magic Wand fills nested metadata from notes

    Pre: Same as above; network online.

    1. Add photo; enter notes that match Smart Description intent (e.g. date + condition).
    2. Tap wand; wait for completion.
    3. Review nested fields; edit one value manually.
    • Toast/message like “Filled N metadata field(s) from the photo notes”.
    • Nested fields show AI values; manual edit persists.
    • Photo notes remain unchanged.
    TC-IWM-004

    Delete photo removes its notes and metadata

    Pre: Item has ≥2 photos on an Image with metadata field.

    1. Open photo A; confirm it has notes + metadata.
    2. Delete photo A (confirm dialog on web).
    3. Inspect remaining photos and the field answer.
    • Confirm copy appears (web): “Delete this photo and its notes?”
    • Photo A, its notes, and metadata are gone.
    • Other photos unchanged; field still counts as filled if ≥1 photo remains.
    TC-IWM-005

    Mobile voice note on photo (online vs offline)

    Pre: Mobile inspection; Image with metadata photo open.

    1. Offline: tap mic “Notes on this photo”, record, stop.
    2. Go online; wait for transcription state to clear.
    3. Run wand after transcription text is present.
    • Offline shows “Voice notes transcribe when you are online” / pending state.
    • Online: “Transcribing…” then note text available.
    • Wand can use transcribed text as grounding.
    TC-IWM-006

    Export / sample JSON shape

    Pre: Checklist with Image with metadata; inspection has one photo with metadata + note.

    1. Open report mapper / export sample JSON for the form (Train Billie / export preview).
    • Sample shows an array of objects with id, url, notes, metadata.
    • Metadata keys map to nested fields (by id or label slug per export path).
